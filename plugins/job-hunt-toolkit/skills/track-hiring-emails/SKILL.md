# Track Hiring Emails

Process inbound hiring messages and keep application records current.

## Provider

- [Gmail provider agent](../../agents/gmail-agent.md)

Select the provider agent for the connected email integration. Stop when no matching provider agent is available.

## Constraints

- Never send, reply to, archive, delete, or otherwise triage email.
- Keep each immediate `jobs/<company>/company.md` as the only source of application status.
- Treat root `APPLICATIONS.md` as a disposable index generated by `sync-application-statuses.sh`.

## Inputs

- Workspace: `JOB_HUNT_WORKSPACE`, or `~/Documents/job_seeking` when unset.
- Trigger: a scheduled poll, or provider message IDs supplied by a webhook or event adapter.

Webhook and polling adapters only supply candidate message IDs to the same provider workflow.

## Workflow

1. Resolve the workspace and require `sync-application-statuses.sh` at its root.
2. Execute the selected provider agent with the workspace path and trigger input.
3. Surface every requested user-review case without changing its application status.
4. Report counts for processed, unrelated, updated, review-required, and retryable messages.

## Completion contract

A message is complete only after the provider agent classifies it and every required file write succeeds. The provider checkpoint marks completion. A failure before that checkpoint remains retryable.

Never persist full message bodies, recruiter contact details, credentials, account identifiers, or raw provider message IDs in workspace files or logs.
